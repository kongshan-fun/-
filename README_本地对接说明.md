## 重要设计规则

1. 每个境域解锁一个新阶的储物袋；在炼器室炼制**一次**后属于当前角色当前档位，不占实体背包重量，无须手动装备。不同阶可共存，但效果永远只取其中**额外负重最高的一件**。
2. 普通一至十二阶增加负重：32、55、80、110、145、185、235、290、355、430、520、630；**杀神储物袋 +780**（本世击败 100 只真实妖兽自动发放）、**虚空储物袋 +1250**（秘境首次成功完成不同探索格/守卫战时独立 1% 掉落）。
3. 虚空储物袋不是进入一次秘境保证出现；成功结算且从未完成过的**每个节点**判定一次，无保底，不能在同格重复点击重抽；已经获得后不再判定。战斗失败不判定。
4. 杀神储物袋的“100 杀”采用现有 `s.stats.kills`，普通妖兽和首领计入，洞府安全试剑不计入；导入旧存档若已经达 100 杀则自动发放。
5. 只扩容随身**负重容量**，不是增加装备位、武器栏、储物箱格数，也不修改法器战斗力。储物袋不能存仓、出售、分解、丢弃或重复炼制；寿尽开新档后重新取得。

## 实施方式

V90.6 不引入服务器或资源文件。储物袋配置注册在 `QData.STORAGE_BAGS` 和 `QData.RECIPES` 中；独立永久拥有标记放在当前角色存档 `storageBags` 中，旧存档缺少该字段时自动补空，不修改原 `version:14` 和本地存档命名空间。`Game.capacity` 使用 `baseCapacity + storageBonus`，所以原采集、拾取、仓库取物、补给等实际负重检查自然生效。`QGame.craft` 仅在本境、材料、炼器室条件满足时建立一次性拥有标记。图鉴新增储物袋分类、14 个固定条目和来源/材料/容量/永久规则，并提供跳到可用配方的按钮。背包顶部可直接查看当前生效等级和特殊储物袋进度。

## 快速复建与回归

```bash
python3 tools/build_v906_storage.py
node tests/v906-storage-regression.test.cjs
node tests/v906-quest-regression.test.cjs
node tests/v906-100-slots-regression.test.cjs
python3 tests/v906-browser-ui.py  # 需要 Playwright + Chromium；默认示例可执行文件 /usr/bin/chromium
```

构建器会验证所有被替换位置均只出现一次；重建不修改 V90.5 文件。跨本地工程合并时按实际差异迁移配置与行为，不要把 `storageBags` 当作可以丢弃的普通物品。

## 尚未通过的发行门禁

- 没有在真实 Android/iOS 手机或 TapTap 内嵌 H5 环境上测试；Chromium 浏览器演示用受控内存 `localStorage`，因此不代表长期真实浏览器持久化已通过。
- 没有进行完全自然素材获取、非增强战力通关十二境和真实经济曲线平衡认证；既有 100 档回归是加速补给与测试战力的里程碑检查。
- 1% 独立概率没有保底，不意味着每次进入秘境就必有一个储物袋；玩家长期体验需要正式服留存数据校准。
- GitHub `main` 不包含这份本地候选版；需要 OWNER REVIEW 后再提交并合并。
