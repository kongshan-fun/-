## 问题
原引擎的采集、勘察、击杀和世界任务统一调用 `xpRatio(kind)`，该函数以**玩家当前境界基础值**计算；地图等级、`RES[k].xp` 与 `ENEMIES[id].xp` 主要未参与奖励结算。故高境角色在第一张图重复采集普通灵草，即可领取高境修为。战斗日志以怪物配置表 `e.xp` 展示，与实际入账不一致。

## 本轮规则（原有玩法，不引入新系统）
- 玩家修为需求、36级／12境、寿元、突破和渡劫条件**保持不变**。
- 普通走路不奖励修为。
- 采集、勘察、怪物、首领和世界主线事件按**地图索引**读取 `REALM_BASE[zone]`，不再按玩家境界读取。
- 地图基准：`round(REALM_BASE[zone] / XP_RATE[kind])`，`kind` 为 `chore` / `mob` / `boss` / `main`。
- 采集同图阶级权重：`clamp(.85,1.6,.85 + .15 * RES[source].xp)`（最小评级1，最高按8计算）。
- 击杀同图阶级权重：`clamp(.65,1.4,1 + .14*log2(enemy.xp / reference))`。普通怪参照本图首领 `xp/4`；首领参照本图首领 `xp`。
- 入账后依旧由现有 `xp()` 应用种族命格修为加成与余数滚存；`gainWorldXp()` 返回本次真实入账值，战斗日志、奖励面板和采集提示使用这个值。
- 洞府吐纳、修为丹、赋灵等自主修炼仍使用现有角色境界成长公式；常规炼制不新设可重复刷取修为。
- 不新增持久化字段，旧存档可按原格式载入。
