# V90.75 迁移与回滚

## 升级前

在旧版本“设置 → 存档与备份”导出JSON，保留原始文件与旧游戏包。不要清浏览器缓存或站点数据，不要用唯一的真实档做故障实验。

新包仍用原有难度、种族、档位命名空间。同一浏览器来源可识别旧档。跨域、跨设备、换文件路径时必须通过导出/导入，不保证浏览器自动共享存档。

## 自动合并

本次把角色内部的12座地图洞府合并成1座全局洞府，不把不同角色、不同难度或不同档位合并。保留当前地图和坐标、随身物品、装备、境界、修为、永久储物袋、轮回玉和已做故事选择。

各设施分别取最高等效阶数；旧1/2/3/4/5阶对应新1/3/5/9/12阶。全部仓库材料合计，全部存放装备保留；装备ID按现有存档规则检查唯一性。旧地图洞府清空为占位数组，重复载入不再重复相加。

旧灵田最多3轮已成熟产出合计保留，未满一轮的时间取已积累的最长部分。迁入超出当前仓房容量时不截断、不卖掉；可以取出，但在降至容量以内前不能继续存入。未建仓房的旧灵田产出保留，建仓后可领。

第一次覆盖升级前主存档之前，写入独立的 `-pre-global-home-v975` 原始归档并读回核验。归档写入失败时，中止主档保存。界面提示存储受限时，先导出，不要通过清站点数据“解决”。

## 导出升级前原档

进入角色后：设置 → 存档与备份 → 导出 V90.75 升级前存档。导出的JSON包含完整旧版state，不是新版裁剪数据，可配合对应旧版游戏回滚。

对更早期没有rebuilt标记的旧档，仍沿用V90.74明确重构/补偿规则；不能把此类旧档宣称为无损换算。本版主要无损合并已经采用当前十二境规则的V90.64–V90.74角色洞府。

## 回滚

1. 额外导出当前V90.75进度留存。
2. 使用隔离浏览器资料或不同静态站点打开原V90.74游戏，避免旧版自动覆写新版命名空间。
3. 导入升级前归档的JSON，核对角色、境界、仓物及地图后再继续。

**不能将V90.75的homeSchema新结构直接交给V90.74继续保存。** 旧版不知道全局洞府、十二阶设施及新增补给，可能忽略新字段。回滚会回到升级前时点，升级后进度不会神奇合并进旧版。

## 存储边界

浏览器localStorage不提供跨多键事务或服务端可信余额。现有测试覆盖单写入故障、重试、档位隔离和幂等，但不等同于真实多设备云存档冲突或多标签并发全覆盖。主存档、归档和自动备份占用额外空间；保存失败必须先导出，不能默默删除原档。
