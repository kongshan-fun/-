# 《山野修仙记》V90.4｜主线子页面与 100 档自动化通关验收

**版本基线：** V90.3 主线引导与地图标识优化版  
**交付分支：** `feat/v90-4-quest-subpages-playthrough`  
**结论：** 主线子页面的代码与自动化导航 PASS；100 档资源补足型加速通关 PASS；完全自然采集、数值平衡、真机视觉尚未验收。未部署、未合并 main。

## 一、界面重构

- 旧“本境探索与生存指引”和“凡界十二境进度”原地折叠框改为两张清爽入口卡片。点击后进入原游戏面板内的完整独立子页，而不是外链或另起网页。
- 探索指引页：当前境域、当前目标、准确点位和原本四类游玩提示；完整独立纵向阅读。
- 十二境进度页：由当前档案 `s.cleared`、`s.ritual` 和 `s.unlocked` 真实状态动态展示十二境；不会把已进入但未击败首领的地图写成通关；补充人/妖的境界线说明。
- 返回路径统一：子页页眉左侧“返回主线”、右上角返回、页底返回按钮、按 Esc 返回，以及底部主线导航返回。返回后恢复进入之前的主线滚动位置与焦点，子页无需单独叠加第二滚动区。
- 首次进入子页的浏览位置归零；主线重绘、换档/切换种族不沿用前一档的子页临时状态。只改 UI，不引入存档字段，不改变地图、战斗、掉落、突破、饥渴、剧情数值。
- 延续原有暖白松绿 / 极简黑白 / 流光仙境视觉，不新增概念图或素材。

## 二、100 档通关测试——范围与实测结论

### 样本设计
- 样本：100 个全新独立存档；人族 50 档、妖族 50 档；每档确定性独立随机种子。
- 使用现有 `QCharacterSlots.newGame`、`QCharacterSlots.save/read/status` 和 `QGame.act` 创建、保存、恢复、操作，没有直接把 `cleared`、`major` 或 `ascended` 写成目标值来伪装通关。
- 每档从首图开始经过实际地图移动、定居、建造山门/祭坛仪式、十二个首领战斗结算、丹霞三层雷劫、婴灵三层问心、七次高境主动破境、飞升界碑结算、最终存档读取与档位检查。
- **明确加速条件**：测试主动补充食水、恢复气血与灵力、提供所需道材、通过游戏 `xp()` 快速获得足够修为/道行，战斗回合临时设置极高攻击以缩短流程。加速攻击不会作为真实档案面板能力持久化。

### 核心结果

| 项目 | 数量 | 结果 |
|---|---:|---|
| 独立角色档位 | 100（50+50） | PASS |
| 十二境通关及首领结算 | 1,200 | PASS |
| 修复仪式／立山门 | 1,200 | PASS |
| 高境主动突破 | 700 | PASS |
| 凝丹雷劫 + 元婴问心步骤 | 600 | PASS |
| 地图移动 | 9,000 | PASS |
| 保存并读取验证 | 3,300 | PASS |
| 成功飞升的独立角色 | **100/100** | **PASS** |

上述为加速条件下的**完整里程碑贯通测试**，证明状态机没有在这 100 个确定性种子与档位组合上卡死，涵盖真实的存读档与游戏行动接口。**不等于 100 次从零自行采集、普通战力战斗、无资源注入的自然玩家通关。** 目前不能据此宣称游戏经济、装备掉率、寿元与难度均已平衡。

## 三、独立 CI 与证据

GitHub Actions 工作流：`.github/workflows/v904-regression.yml`（Node.js 22）。

三个执行项：
1. `node tests/v904-quest-subpages.test.cjs`（主线两个子页面、返回与滚动恢复）。
2. `node tests/v904-100-slots-playthrough.test.cjs`（100 个独立存档十二境加速通关）。
3. `node tests/p10-nine-heavens.test.cjs`（原飞升功能回归）。

CI 额外生成 Artifact：`V904_100Slots_Accelerated_Proof`。内含合成最终存档 JSON 共 100 份、每档结果清单与中文 README，由 GitHub Actions 自动打包下载；这些属于**测试夹具存档**，非玩家原始档案，不应当作为普通体验或战力平衡展示。
