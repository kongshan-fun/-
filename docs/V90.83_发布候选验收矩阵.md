# 山野修仙记 V90.83｜TapTap 发布验收矩阵

发布基线：V90.82 已合并主线 + PR #32 的云恢复与广告幂等修复及进一步存档校验。

## 自动化门禁
- 从冻结源与仓库内适配层确定性重建 HTML；构建产物与提交文件字节一致
- V90.81 修为经济与 V90.82 P0/P1 存档回归无退化
- V90.83：双种族三难度的主存档识别；双档原子恢复；恢复前备份失败保护；第二档写盘失败/静默损坏/旧键清理失败回滚；云端 JSON 损坏或角色/难度不符拒绝覆盖；云上传读取故障时失败而不上传残缺档案
- 激励视频：同一次请求失败回调与重试拒绝不得重复发奖；完成回调重复触发不得重复发奖
- 排行榜：新版 v982 本机分榜纳入云备份；简单档不上报官方榜
- Chromium：320、360、390、412、1440 五视口，模拟 TapTap 宿主初始化、触摸页面、无 JS 报错、无横向溢出、真实截图
- ZIP：唯一游戏入口 shanye-v983/index.html；压缩包与候选 HTML 字节回读一致；附 SHA256 核验信息

## 仍需实机与后台确认
- 真实 TapTap SDK 云存档：同账号双设备、已存档设备、无档设备、断网恢复、异常返回时本机存档安全
- 真实广告：看完、提前关闭、错误回调、网络差、恢复应用时发奖一次性
- 榜单：标准与挑战 IDs 独立，简单档无任何上报；真实榜单读数
- 真实手机触摸、后台切换、旧玩家导出及回导
- TapTap 后台主包状态、审核回执、版本号及 Owner 最终批准

只要未完成上述真实平台验证，CI 通过仍不能宣布正式线上已发布。

## 官方榜单发布锁（新增）

V90.83 的修为/战斗平衡与 V90.78/V90.80 规则不同，不能重用旧 TapTap 战力榜和飞升榜客户端 ID。适配层默认关闭官方排行榜提交及打开（本机 v982 分榜正常、仍参与云备份），避免新旧赛季串榜。**发布前**须在 TapTap 后台创建、核实挑战与标准各自独立的战力榜和飞升榜共四个新客户端 ID，再通过 `__SHANYE_V983_OFFICIAL_BOARD_IDS` 配置。当前 GitHub 仓库不含这些新 ID，严禁自行编造。没配置真实榜单时只可开展不污染旧榜的技术/提审测试。

新增历史防护：识别 V11 剑修/丹修及 V10、V9、V8、V7、V5、V2、V1 真实旧档，禁止自动云恢复覆盖；这些键也进入云同步收集。
