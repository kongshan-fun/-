## 二、发现的阻断性缺陷（重要，需要云端修）

### 缺陷：V90.78/79 的灵田归档让「老档无法保存」

复现与定位（引擎级）：

```
QCharacterSlots.save('human', game, 1)
  → 抛错：旧灵田归档身份不符
```

源码位置（V90.79）：

```js
RaceSlots.prototype.save = function (id, g, n = 1, options = {}) {
  for (const key of [this.key(id, n), this.backupKey(id, n)]) {
    const raw = this.readKey(key); if (!raw) continue;
    const old = JSON.parse(raw);
    if (old.version !== 14 || !old.rebuilt || old.garden !== undefined) continue;   // 新档/已有灵田 → 跳过
    if (old.race !== id || old.difficulty !== this.difficulty) throw Error('旧灵田归档身份不符');
    ...
```

V90.61 时代的老档 **没有 `difficulty` 字段**（难度是 V90.64 才加的）→ `old.difficulty !== 'challenge'` 成立 → 抛错 → `persist()` 失败。

玩家侧表现（已实测）：设置页存档状态显示「未能落盘 · 请导出」，吐纳/采集等任何动作都不写盘，**进度全丢**。

本地临时修（P9，只放宽缺字段的情况，不放过真正的跨难度冲突）：

```js
if (old.race !== id || (old.difficulty !== undefined && old.difficulty !== this.difficulty)) throw ...
```

修后：`v929 存档往返` 从 23/24 变 **24/24**，全量回归从 36/43 回到 **42/43**。

**建议云端在 V90.80 里正式修**：迁移阶段给老档补 `difficulty:'challenge'`（或如上放宽判定），并加一条「老档首存」回归。
