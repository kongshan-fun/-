## 一、二审审了什么，发现和处理了什么

### 审查对象

- 三档难度的要求：easy 0.5 / standard 0.8 / challenge 1.0。
- 修炼经验所需、敌方气血/攻击/防御、雷劫固定伤害；玩家基础属性/掉落概率不改变。
- 开局交互：难度选择 → 种族 → 档案 → 天赋与加点 → 真正创建角色。
- 双族 × 每模式 100 档 = **600 个逻辑档位**；相应主档、备份、死亡标记、轮回玉账本、命格广告机会分模式隔离。
- 旧存档：未标记 `difficulty` 的 V90.62 存档只属于 challenge，原本挑战档案与榜单的 storage key 不变。
- 本机榜：easy 不记名次，standard 与 challenge 有各自独立榜。
- TapTap 官方榜：easy 不得提交；standard 无官方独立排行榜 ID 时不得提交到原 challenge 榜。
- 冻结发布 HTML、入口文件、锁定构建器及手机三/六视口。

### 这轮发现并实际处理

1. **妖兽图鉴数值与难度脱节（已修）**：原先始终显示 100% 基础气血、攻击、防御，导致简单/标准玩家看见与本模式不一致的基础值。现在根据当前角色难度倍率展示，并注明越级压制和复战系数尚未计入。
2. **妖兽图鉴掉落描述过期（已修）**：仍写“首领必掉一件法器、野怪22%掉法器”，与 V90.23 已实施的“战斗不掉成品，首领另给炼器灵材和灵尘”冲突。已经改为实际掉落规则，不调整掉落数值。
3. **测试未覆盖真正的开局提交（已补）**：上一轮 69 项浏览器测试直接通过 JavaScript 创建模拟角色，无法代替点 UI 真实建档。补 `tests/v964_second_audit_browser.py`：三种难度由实际按钮抽命格、确认属性、生成游戏、读取真实 localStorage、刷新续玩；还走真实设置→档案→难度切换和跨模式 JSON 文件导入拒绝路径。
4. **历史全量回归存在版本覆盖误读（已明确）**：`tests/run_full_regression.cjs` 的多个浏览器层引用 `play/jindan-vNNN` 冻结历史文件；历史 `43/43` 不能被写成“直接验证当前 V90.64 的 43 层”。本次使用真正从 V90.64 `index.html` 启动的专项 Chromium 验收补足当前改动的覆盖；但不是对历史 43 层全部重新验证。
5. **中间 CI 红灯（已闭环）**：曾因旧界面测试定位错误、教程弹窗未按“自行探索”关闭及构建哈希未更新而失败。最终测试不放宽核心断言，只按实际用户操作修正脚本；图鉴源文件、发布文件、构建器现有精确 SHA 校验一致。

## 三、重要边界：本地交付可用，TapTap 正式上线仍 BLOCKED

1. **标准模式 TapTap 在线排行榜仍缺少真实官方 ID**：应由后台新建与挑战榜隔离的标准战力榜、标准飞升榜。构建器接收 `TAPTAP_STANDARD_POWER_ID` 和 `TAPTAP_STANDARD_SPEEDRUN_ID`，但不得凭空捏造。未配置时保护逻辑阻止向挑战榜错误提交。
2. **TapTap 适配层版本与来源还未锁定**：当前平台构建器依赖仓库外 `../shanhe-v907/taptap/taptap-adapter.js`，所以仅凭本 GitHub 分支无法证明重新做出的平台包与已上传的历史包相同。这是 V90.63 平台修复工作包的 Gate A。
3. **真实 TapTap 云存档/激励广告/双设备与旧档重置尚未完成平台验收**。不能因 H5 浏览器绿灯就称平台安全，尤其不能未备份真实玩家唯一旧档便尝试重置。
4. **模式切换不互通≠设备之间云存档永久隔离**。当前平台适配器仍需审核恢复时是否有覆盖其他模式键的行为；在该专项未闭环前，不使用本包提交审核。
5. **未完成全部 V90.64 历史 43 层对当前新入口的重跑**：本地 AI 接手后应明确将旧版测试的冻结依赖拆出，对当前页面可适配的 UI 套件改成直接读取本版本，以本版实际提交留新证据，不能伪造旧回归 43/43。
