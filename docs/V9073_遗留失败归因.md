> 结论先说：**这 4 层里没有发现产品缺陷**。三层是「旧测试流程与 V90.64 难度门/界面改版漂移」，
> 一层（轮回玉广告）也是测试的导航选择器失效——它们各自的关键行为我都用直接驱动方式验证过，均正常。

- 四层在 **V90.64 与 V90.73 上表现完全一致** → 与本次改动无关。

## 直接驱动实测（绕开测试脚本）

### 1. 旧档缺字段补齐 — 正常

删掉存档里的 `gears` / `manuals` → 重载 → 触发一次保存：

```
初始存档    keys=63  gears=0    manuals=6 键
删后重载    ——
保存后      keys=66  gears=[]   manuals=6 键   ritual=12
```

补齐逻辑在 `normalize()` 里：`fresh()` 先给出默认值，再按 `o.gears`/`o.manuals` 逐项白名单合并；
缺失字段不会丢、不会把整块换成默认空值。

### 2. 续命 +10 年 — 正常

```
点击前 60.0 年 → 点「续命+10」→ 点击后 70.0 年，提示「本世寿元+10年」
```

### 3. 寿尽救援 — 正常（含「每世一次」）

```
寿元 2 分钟 → 触发耗时动作 → 弹「还有一线生机」救援弹窗
点「看广告续命」→ 15.0 年、rescued=true、ended=false（未结算）
再次耗尽 → 直接进「本世结算」permadeath，不再给救援
```

### 4. 轮回玉广告重复领取 — 测试卡在导航

失败点在第 1 步「进入 002 档命格确认页」= `null`，
即测试的导航选择器（V90.9 时代的档案页动作名）在 V90.64 难度门之后已不匹配；
它连「领取 100 轮回玉」按钮都没碰到，因此**没有证据表明奖励逻辑有问题**（"002 档没有 -jadead 键" 这类断言反而是 PASS）。

## 为什么这 4 层在其原 fixture 上能过、在 V90.64+ 上过不了

V90.64 引入「入世第一步：选择修行难度」后：

1. 页面不再直接进入游戏，测试原有的「等 `!view-slots` 即算入世」判定会抢跑（空白页也满足）；
2. 档案页动作从「顶部档案 → 列表」改为「难度 → 种族 → 档案 → 001 档」，旧测试里
   `[data-a]` 名称/层级对不上；
3. 人物装备面板测试需要**带装备的档**，而共用种子（v961）里 `gears` 为空 → 渲染 0 张卡。

## 建议（按性价比排序）

1. **修测试，不改产品**：把 4 个测试的入世与导航改成 V90.64 流程（复用我新写的
   `make_play_fixture.cjs` 自动入世 + `[data-a="slot-open"]`），并给装备面板测试准备带装备的档。
2. 轮回玉广告测试单独重写一次导航，再判断奖励逻辑是否真的可重复（设计上「可重复领」是既定行为，
   这条测试本意是**守住**可重复，不是禁止）。
3. 越级压制那 2 项（`开局对手攻击 × enemyBoost`、`开局对手气血 ÷ playerDampen`）是断言口径问题：
   测试假设「开局敌人属性 = 基础 × 加成」，而 V90.51 之后开局敌人走 `earlyStats` 通道，
   需要按新公式更新期望值。
4. `file:// 双击直开` 测试硬编码在找「入世入口」，那是 V90.64 之前的入口形态，应改为检查
   「难度选择页是否渲染」。
