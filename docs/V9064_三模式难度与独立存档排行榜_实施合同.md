# V90.64 三档难度、独立存档与双排行榜实施合同

状态：**设计与实现门禁定稿；代码尚未完成；不得当作已经发布的功能。**  
基线：2026-10-23 的 GitHub main / V90.62。  
施工分支：`feat/v90.64-three-difficulty-modes`。  
本功能为新玩法版本 V90.64，避免与已规划的 V90.63 平台修复专项混淆。

## 一、玩家可见的设计

采用“难度 → 种族 → 所选难度的存档位 → 角色创建/继续”的顺序。第一次打开优先显示难度页；已有角色也通过入口页选难度。三张难度卡一次只能进入一种模式；不使用竖屏顶层多个可滚动区域。

| 难度 | ID | 修为升级要求 | 敌方属性 | 排行榜 | 预期玩家 |
|---|---|---:|---:|---|---|
| 简单模式 | `easy` | 当前挑战公式 × 0.50 | 当前挑战公式 × 0.50 | 不提交，不展示竞争榜 | 体验地图、炼制与剧情 |
| 标准模式 | `standard` | 当前挑战公式 × 0.80 | 当前挑战公式 × 0.80 | **标准榜**，独立 | 大多数新玩家 |
| 挑战模式（硬核） | `challenge` | 当前公式 × 1.00 | 当前公式 × 1.00 | **挑战榜**，独立 | 老玩家/高手 |

**当前 V90.62 的所有数值即挑战模式，完全不改变原难度体验。**
本次先约定“升级所需经验”=境基础修为需求 × 阶段系数 × 难度系数；修为获取产出不额外乘难度（简单模式因此更容易升级）。敌方属性至少覆盖最终战斗用气血上限、攻击及护甲，应用在启动战斗时一次，存档中保存已经计算后的怪物数值；刷新/重开时优先恢复存储值，不重复乘难度。木傀训练不视为野怪，不需要削弱；渡劫固定雷伤、玩家基础属性、资源掉落、炼制和广告奖励暂保持现有规则，防止影响 V90.62 已平衡的其他数值系统。如产品后续另要降低渡劫伤害，单独提案与验证。

展示文案：“简单 · 50% 需求及敌方强度 · 不计排行榜”“标准 · 80% 需求及敌方强度 · 独立标准榜”“挑战 · 100% 原始难度 · 独立挑战榜”。显示为只读说明，不误做成可再调的滑杆。

## 二、存档及身份不可破坏的约束

1. 难度是**角色创建时确定、终身不可变**的进度身份字段：`difficulty: 'easy' | 'standard' | 'challenge'`。凡是加载、导入、保存、轮回、归档、奖励和排行榜都验证身份。
2. 三难度 × 两种族 × 每种族 100 档，逻辑上共 **600 个隔离槽**。不得仅通过 UI 隐藏其他存档实现“隔离”；底层主档、自动备份、死亡标记、轮回玉账本、命格抽取次数、奖励回执都需区分难度。
3. **保留现有挑战模式的所有存储键原样不动**（旧数据缺 `difficulty` 字段按 `challenge` 解释）；`easy` / `standard` 使用版本化前缀新命名空间，不覆盖、移动、升级或删除原存档。旧存档恢复后默认进入挑战模式。
4. 从标准档导入简单档、从挑战档导入标准档、跨难度覆盖存档、跨难度转移轮回玉及天赋，必须由引擎/存储层拒绝，不能只靠前端弹窗。
5. 不允许简单存档的飞升、死亡奖励、导入 JSON 或排行榜数据注入到标准/挑战排行榜。挑战旧榜应保留历史成绩，但必须标注“挑战榜”；标准榜从空榜开始。
6. 开局模式菜单中允许查看标准/挑战的排行榜，但简单榜隐藏或明确为“休闲模式不排名”；世界内排行榜只显示当前难度。种族筛选可保留在每个难度榜内。
7. 平台云存档应与模式 + 种族 + 档位绑定唯一身份；云端同步时不得把某一模式备份恢复进另一模式；包体同步扫描键范围需更新并设置回归断言。
8. 若现有 TapTap 排行榜平台只支持单一排行榜 ID，则**不能把标准与挑战提交到同一云榜**；需在平台创建/配置两个经核实的榜单 ID，再做服务端分流。简单模式不触发排名提交。平台未配置成功时可以只做本地双榜候选，发布门禁继续 BLOCKED。

## 三、代码接入点（已核查的 V90.62）

- 数据层 `fresh()` 和 `normalize()`：添加、回读并校验 difficulty，历史缺值 = challenge；错误值拒绝/安全处理而非默默跨模式。
- `Game.required`：修为需求计算倍率（最小 1，明确四舍五入）。
- `Game.startBattle()` 及 `normalize() combat`：初次生成怪物 HP/ATK/armor 应用倍率；恢复时优先保存的 HP/ATK，缺损字段才算难度倍率。
- `RaceSlots`：按难度隔离 `key/backupKey/deathKey/legacyKey`；确保旧 challenge 键完全保持；`save/newGame/read/resetRebuilt/migrate` 做交叉模式校验。
- `QEntry` 纯视图、`renderPage/showPage/handle`：进入游戏先选择难度，再选种族；角色页返回可回难度页；触屏点击区域至少 44px；固定布局可在单一内容区滚动。
- `leaderboardKey/leaderboard/recordAscension/leaderboardBody`：简单跳过记录，标准与挑战各自使用独立榜键与显示。老成绩仍落挑战榜，不把新标准成绩混入。
- `tools/build_taptap_*` 和实际 `taptap-adapter.js`：新增 mode 到云存档和榜单上报 identity；不要只修改本地榜面板。
- 辅助存储 `drawKey`、临时命格草稿、加点、遗泽等也必须做同模式隔离。
