## 三、发现的两个隐患（不影响本次上线，建议下一版处理）

### 隐患 A：速通上报的「难度一致性校验」是死代码

```js
q.leaderboard.submitAscension=function(record){
  const mode=currentMode();
  if(record?.difficulty && record.difficulty!==mode) reject(...)   // ← 永不触发
  return guard('submitAscension','speedrun',[record]);
}
```

游戏的 `ascensionRecord` 字段只有 `version / race / runId / elapsedMinutes / remainingLifeMinutes / defeats`，**没有 `difficulty`**，
所以这个校验恒不触发。实际隔离仍靠 `sync()` 的当前模式，不会串榜；但这行等于没写。

修法：在 `ascend()` 生成 `ascensionRecord` 时补 `difficulty: this.s.difficulty`（存档校验那一关也放行该字段）。

### 隐患 B：云存档恢复是「整包替换」，可能吃掉未上传的新档

`applyPayload()` 先删除本机所有 `isGameKey` 键，再写入云端快照。
如果云端快照比本机旧（比如本机新建了标准档但还没上传就点了恢复），新档会被旧快照覆盖。

修法（任选）：
1. 恢复前自动先做一次本机快照导出（本地文件备份）；
2. 比对 `payload.ts` 与本机最新存档时间，若云端更旧，弹窗提示「云端较旧，仍要恢复？」；
3. 恢复时改为「按 key 合并」，不删除云端快照里没有的本机键。
