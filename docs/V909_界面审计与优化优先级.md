# V90.9 界面审计 · 哪些界面需要优化

> 方法：用零依赖 CDP 在 390×844 真实打开每个面板测量版面（横向溢出、内容高度/可视高度比、
> 按钮数、标题数、容器内溢出、最长段落），再对渲染函数做静态结构统计，
> 并对关键面板逐张看截图确认。
>
> 脚本：`tests/v909_panel_audit.cjs`（运行时）、`tests/v909_static_audit.cjs`（静态）
> 产物：`visual/v909-audit/audit.json`、`static-audit.json`、`panel-*.png`

## P0 · 必须改：图鉴（book）

**证据**：内容高 **14,456px**，可视 561px → **25.77 屏**；192 条条目；0 个分区标题。

症状：
1. 192 条全量平铺，一屏只能看 4 条，找一件材料要滚十几屏。
2. **成就进度块压在列表最上方**（初识山野 6/10、行遍山川 6/25、博览五境 6/45、万物初识 6/80、九天见闻 6/110），
   占掉首屏约 1/3，把真正要查的条目挤下去。
3. 每条是一张 ~137px 的高卡片，信息只有「名称 + 类别 + 已识 ›」，密度极低。
4. 「未达成」被渲染成**按钮**，但点了没有任何操作——是状态却装成可点控件。

建议方向：成就块与图鉴条目拆开（成就移回主线/里程碑）；条目改为紧凑列表或双列网格；
按类别分组并提供吸顶分类筛选（现有「全部」下拉已具备筛选骨架，缺的是分组与密度）。

## P0 · 必须改：炼制（craft）

**证据**：内容高 1,236px / 561px → 2.2 屏；**12 张配方卡、0 个 h3**；12 个动作。

症状：
1. 12 张配方卡**完全平铺**，没有按「工具 / 武器 / 护具 / 丹道 / 储物袋」分组。
2. 可制的只有 1 张（粗木斧），其余 11 张都是「缺材料 / 缺设施」，**与可制卡同样大小同居首屏**。
3. 缺材料只显示 `灵木 2/2` 并加下划线，**不说明去哪采**（和我在 C 任务里做的材料来源指引没有打通）。
4. 「炼器室 1 阶 · 未就绪」措辞含糊：是没建炼器室，还是等级不够？玩家分不清。

建议方向：按可制优先排序 + 分组标题；不可制折叠或降级为紧凑行；
缺材料处直接复用 `progMatSource()` 给出真实来源与采集耗时；状态文案改成可判定的具体原因。

## P1 · 建议改：背包（pack）

**证据**：首屏 619px 内塞了储物袋大卡 + 3 个操作按钮 + 1 个标题 + 6 个物品行；11 个按钮。

症状：
1. **储物袋卡占首屏约 1/3**，而它此时是「尚未炼制」的空状态，信息密度极低。
2. 物品行高约 137px，一行只有「灵木 ×2 + 丢1」两个信息点，一屏仅 6 件；材料种类一多就要长滚。
3. **无分类、无排序、无筛选**：材料 / 食物 / 丹药 / 矿物混排。
4. 「材料入仓」是禁用按钮，但**没说明为什么禁用**（实际需要「洞府内 + 已建仓房」）。
5. 「人物 · 穿戴装备与精炼」是孤立底部跳转按钮，视觉上不属于任何分区。
6. 每行都有「丢1」，且是主按钮尺寸，**误触风险高**。

建议方向：储物袋卡折叠为一行摘要（有需要再展开）；物品行压缩为单行列表；
加分类分段；禁用按钮补一句原因；丢弃改为长按或二次确认。

## P1 · 建议改：功法（manuals）

**证据（静态）**：函数体 6,630 字符，**0 个 h3**，7 个动作，最长文本块 115 字。

症状：整页没有任何分区标题，功法条目、装配槽位与说明混排在一起；
条目信息靠卡片自带样式区分，缺少「已学 / 可学 / 宗门传承」的段级分隔。

建议方向：按「已学 / 可学 / 装备槽」分段；条目压缩为紧凑行 + 展开详情。

## P1 · 建议改：洞府（camp）

**证据**：**144 字**的超长段落 2 处；6 个动作、9 个按钮。

症状：选址说明与建筑说明是成段的散文，长段挤压按钮；
建筑条目的「成本 + 升级按钮 + 效果说明」没有统一的行结构。

建议方向：长段拆成要点；建筑统一为「名称 / 当前等级 / 成本 / 效果 / 按钮」五行结构。

## 横向共性问题（跨面板，值得先定规范再逐个改）

1. **卡片密度不一致**：图鉴 / 背包物品行高约 137px，炼制卡约 180px，设置模块约 100px。
   同样的「标题 + 一行说明 + 一个操作」在不同面板高度差一倍。
2. **缺分区标题**：`功法和见闻完全没有 h3`，`炼制/仓库/图鉴列表为 0`。
   这直接导致「一屏到底、找东西靠滚」。
3. **状态与控件混淆**：「未达成」「缺材料」「尚未炼制」有时是按钮、有时是文字，可点性不一致。
4. **长段落未拆分**：洞府 144 字、大道 279 字、血脉 195 字，属于手机上一屏纯文字的级别。
5. **材料获取链路断裂**：炼制缺材料时只显示数量，不指路；而 C 任务已经做好的 `progMatSource()`
   目前只服务突破指引，没有复用到炼制/背包/图鉴。

---

## 建议的修复顺序

1. **图鉴**（25.77 屏 → 目标 ≤4 屏）：成就块拆出、条目压缩、分类分段。
2. **炼制**：分组 + 可制优先 + 缺料指路（复用 `progMatSource`）。
3. **背包**：储物袋折叠 + 物品行压缩 + 分类。
4. **功法 / 洞府**：补分区标题、长段拆点。
5. **高境长文面板**（大道/血脉/裂隙/因果）：统一分段规范后集中处理。

在第 1、2 步之前建议先定一条**卡片密度规范**（行高、间距、标题层级），
否则逐个改完仍会出现同样的不一致。
